5th-5M Attendance Portal — Enhancement Notes

The project includes CR and student portals, attendance marking and history, attendance analytics,
student notifications, timetable management, study resources, QR attendance, correction requests,
class hub tools, audit history, and backup tools.

Data-preservation rules:
- Keep the existing DATABASE_URL pointed at the current production database.
- Do not run prisma db push with --accept-data-loss.
- Do not reset, drop, recreate, or seed the production database as part of a UI update.
- Review schema changes and back up the database before applying any schema migration.
- The attendance marking endpoint upserts existing sessions and records; it does not delete records
  that were not included in a save request.
- Changed attendance statuses are recorded in the existing AuditLog table.

Optional Web Push environment variables:
VAPID_SUBJECT
VAPID_PUBLIC_KEY
VAPID_PRIVATE_KEY
NEXT_PUBLIC_VAPID_PUBLIC_KEY

If push variables are not configured, verify in-app notifications independently.
